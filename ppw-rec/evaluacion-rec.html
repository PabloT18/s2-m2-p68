TIPO: Evaluación práctica TÍTULO: Modificación y ampliación de una API REST segura para biblioteca universitaria
OBJETIVO

Evaluar la configuración de una aplicación Spring Boot, la modificación de módulos existentes, la construcción de consultas derivadas con Spring Data JPA y la creación de endpoints públicos y protegidos documentados mediante Swagger/OpenAPI.
INSTRUCCIONES:
  1. Utilice exclusivamente el proyecto proporcionado para Java 17.
  2. Realizar FORK del repositorio proporcionado en el AVAC
  3. Ejecute el proyecto antes de modificarlo. Inicialmente se levantará con la configuración predeterminada de Spring Boot.
  4. No modifique schema.sql ni data.sql.
  5. No cambie rutas, parámetros, nombres JSON, mensajes, códigos internos ni códigos HTTP definidos.
  6. Toda regla de negocio debe implementarse en la capa de servicio.
  7. No se permite retornar entidades JPA directamente desde los controladores.
  8. Todos los endpoints nuevos deben aparecer en Swagger UI con sus parámetros, respuestas y seguridad correspondiente.

CONTEXTO DEL SISTEMA

La universidad dispone de una API para administrar usuarios lectores, editoriales y libros. El proyecto ya contiene autenticación JWT, manejo centralizado de excepciones, persistencia H2 y configuración completa de Swagger/OpenAPI.

La base contiene las tablas users, roles, user_roles, publishers, books y refresh_tokens. La información se carga automáticamente desde los scripts ubicados en src/main/resources.

Alcance: existen seis requerimientos. Los tres endpoints nuevos trabajan exclusivamente con BookEntity y BookRepository.

ACTIVIDADES POR DESARROLLAR

R1 · 3 puntos

Configuración del servidor

Agregar en application.yml la configuración necesaria para ejecutar la API en el puerto 8080 y con context path /api.

Resultado: Swagger debe quedar disponible en http://localhost:8080/api/swagger-ui.html.

R2 · 3 puntos

Configuración JWT

Al iniciar sesión correctamente, la API debe generar una respuesta como la siguiente: 

POST /api/auth/login

{
  "email": "admin@ups.edu.ec",
  "password": "Admin123!"
}
{
  "accessToken": "eyJhbGciOiJIUzUxMiJ9...",
  "refreshToken": "J8kVhvz3W2QyQ1j8_KFh6x90TqzA1yWL6gx0GVMWQsc",
  "expiresIn": 1200000
}

Realizar la configuración necesaria para que el accessToken tenga una duración de 1200000 milisegundos, equivalentes a 20 minutos.

Al decodificar el payload del JWT, el token debe contener el issuer: 

{
  "iss": "ups-library-api",
  "iat": 1785988783,
  "exp": 1785989983
}

La diferencia entre exp e iat debe ser de aproximadamente 1200 segundos.

No modificar el secreto utilizado para firmar los tokens ni la expiración configurada para el refresh token.

Capa afectada: configuración JWT.

R3 · 5 puntos

Modificar usuarios activos por edad

Actualmente el EndPoint esta completamente publico, debe estar protegido por Authenticación y Autorización

Corregir GET /api/users/active-readers?minAge=21. El endpoint debe retornar únicamente usuarios que cumplan:

  • age >= minAge.
  • active = true.
  • deleted = false.
  • Ordenamiento por fullName ascendente.

La respuesta actual tiene el siguiente formato:

[{
  "id": 1,
  "name": "Pablo Administrador",
  "email": "admin@ups.edu.ec",
  "age": 40,
  "active": true
}, ...]

La respuesta esperada debe tener exactamente el siguiente contrato:

[{
  "id": 1,
  "fullName": "Pablo Administrador",
  "email": "admin@ups.edu.ec",
  "age": 40,
  "active": true,
  "roles": [
    "ROLE_ADMIN"
  ]
}, ...]

El campo name no debe aparecer en la respuesta. Debe reemplazarse por fullName e incluirse el listado de roles del usuario en el campo roles.

El endpoint debe quedar accesible únicamente para usuarios con rol ADMIN.

En Swagger, el endpoint debe mostrarse como una operación protegida mediante autenticación Bearer JWT y debe permitir probarse utilizando el token configurado en bearerAuth.

Capas involucradas: DTO, mapper, repository, service, controller, seguridad y Swagger.

R4 · 4 puntos

Modificar consulta de editoriales

Actualmente el EndPoint se consume con cualquier rol, pero si debe esta Authorizado. Debe estar protegido por Autorización

Corregir GET /api/publishers/active?country=Ecuador. El endpoint debe retornar únicamente editoriales que cumplan:

  • El campo country debe coincidir con el parámetro recibido sin distinguir mayúsculas ni minúsculas.
  • active = true.
  • deleted = false.
  • Ordenamiento por name ascendente.

La consulta debe implementarse mediante un método derivado de Spring Data JPA. No se permite recuperar todos los registros y aplicar los filtros desde Java.

El endpoint debe quedar accesible únicamente para usuarios con rol ADMIN o LIBRARIAN.

En Swagger, la operación debe mostrarse como protegida mediante autenticación Bearer JWT y debe poder probarse utilizando el esquema bearerAuth.

Cuando el usuario no esté autenticado, la API debe impedir el acceso. Cuando esté autenticado pero no tenga alguno de los roles permitidos, debe responder con acceso denegado.

Capas involucradas: repository, service, controller, seguridad y Swagger.

R5 · 6 puntos

Crear consulta pública del catálogo

Crear GET /api/books/catalog?minCopies=4. Este endpoint debe ser público y no debe requerir JWT.

Retornar libros con active = true, deleted = false y copiesAvailable >= minCopies, ordenados por title ascendente. Responder siempre 200 OK, incluso con lista vacía.

Debe documentarse con @Operation, parámetro de consulta y respuesta HTTP. En OpenAPI no debe declarar bearerAuth.

R6 · 9 puntos

Crear operaciones protegidas de libros

Completar el módulo books con repository, mapper, service, implementación, controller y excepción.

R6.1 Consulta protegida

Crear GET /api/books/low-stock?maxCopies=4. Retornar libros con active = true, deleted = false y copiesAvailable < maxCopies, ordenados por copiesAvailable ascendente.

Solo pueden acceder ADMIN y LIBRARIAN. Debe declarar @SecurityRequirement(name = "bearerAuth").

R6.2 Desactivación lógica

Crear PATCH /api/books/{id}/deactivate. Solo puede acceder ADMIN. La operación debe asignar active = false y deleted = true, y retornar el DTO actualizado con 200 OK.

El meotodo JPA:

  • findByAgeGreaterThanEqual
  • AndActiveTrue
  • AndDeletedFalse
  • OrderByFullNameAsc

Condiciones:

  • Si el libro no existe o ya está eliminado: 404, código BOOK_NOT_FOUND, mensaje Book not found.
  • Si copiesAvailable > 0: 409, código BOOK_CONFLICT, mensaje Book cannot be deactivated while copies are available.

Crear BookConflictException extendiendo ApplicationException. Documentar en Swagger las respuestas 200, 404 y 409, además de la seguridad Bearer.
