ACTIVIDADES POR DESARROLLAR

1. Contexto

Una empresa de mensajería registra envíos con código de seguimiento, destinatario, prioridad y dimensiones del paquete. Se debe implementar una clase controladora que filtre, ordene, elimine duplicados y clasifique los envíos.

Se evaluará la selección de las implementaciones de colecciones más adecuadas. El enunciado define las interfaces de retorno y el orden requerido, pero no indica qué implementación concreta debe utilizarse.

2. Creación y entrega del proyecto

  1. Crear un proyecto Java nuevo.
  2. Crear los paquetes models, controllers y data.
  3. Descargar el archivo ShipmentData.java proporcionado por el docente.
  4. Copiarlo sin modificaciones dentro del paquete data.
  5. Crear un repositorio personal en GitHub y subir el proyecto completo.
  6. Entregar en el AVAC únicamente el enlace del repositorio.

3. Modelos obligatorios

Crear la clase PackageDimensions dentro del paquete models. 

public class PackageDimensions {
    private double length;
    private double width;
    private double height;
    private double weight;
}

Debe incluir el constructor con los cuatro atributos, sus getters y el método: 

public double getVolume()

El volumen se calcula con: 

length * width * height

Crear la clase Shipment dentro del paquete models. 

public class Shipment {
    private String trackingCode;
    private String recipient;
    private PackageDimensions dimensions;
    private int priority;
}

Debe incluir el constructor con los cuatro atributos y sus getters. No agregar lógica de ordenamiento ni clasificación dentro de los modelos.

5. Método A: filterAndOrderShipments

Retornar los envíos cuyo volumen sea mayor o igual a minimumVolume.

Se peude crear metodos auxiliares

Unicidad lógica:

  • Dos envíos son duplicados cuando tienen el mismo volumen y el mismo código ignorando mayúsculas y minúsculas.
  • Solo debe conservarse una aparición.

Orden obligatorio:

  • Volumen descendente.
  • Si el volumen es igual, código de seguimiento ascendente.
  • La comparación del código debe ignorar mayúsculas y minúsculas.

Condiciones:

  • El resultado debe permanecer ordenado automáticamente.
  • No ordenar primero una lista para después convertirla al tipo de retorno.
  • La estructura concreta debe justificarse en el README.md.

6. Método B: classifyAndExtractShipments

Clasificar todos los envíos mediante una estructura clave-valor y retornar únicamente los objetos de la categoría solicitada en requestedCategory.

Categorías:

  • BULKY: volumen mayor o igual a 120000 o peso mayor o igual a 25.
  • REGULAR: volumen mayor o igual a 30000, siempre que no sea BULKY.
  • LIGHT: los demás envíos.

Unicidad lógica:

  • Dos envíos son duplicados dentro de una categoría cuando tienen la misma prioridad y el mismo código ignorando mayúsculas y minúsculas.

Reglas del agrupamiento:

  • La clasificación completa debe construirse antes de obtener la categoría solicitada.
  • Las claves deben ser exactamente BULKY, LIGHT y REGULAR.
  • Las claves deben mantenerse ordenadas alfabéticamente.
  • Cada grupo debe eliminar duplicados y mantenerse ordenado automáticamente.

Orden dentro de cada categoría:

  • Prioridad descendente.
  • Si la prioridad es igual, código de seguimiento ascendente.
  • La comparación del código debe ignorar mayúsculas y minúsculas.

Retorno:

  • Retornar una nueva lista con los objetos de la categoría solicitada.
  • La categoría recibida debe procesarse ignorando espacios externos y mayúsculas.
  • Si la categoría es nula o no existe, retornar una lista vacía.
  • No se permite filtrar directamente solo la categoría solicitada.

7. Prueba mínima desde Main.java

List<Shipment> shipments = ShipmentData.createShipments();

ShipmentController controller = new ShipmentController();

Set<Shipment> ordered =
        controller.filterAndOrderShipments(shipments, 50000);

List<Shipment> bulky =
        controller.classifyAndExtractShipments(shipments, "BULKY");

System.out.println("Method A: " + ordered.size());
System.out.println("BULKY: " + bulky.size());

8. README.md obligatorio

Explicar para cada método:

  • Implementaciones concretas seleccionadas.
  • Razón de la selección.

9. Restricciones

  • No modificar ShipmentData.java.
  • No cambiar nombres, parámetros ni tipos de retorno de los métodos.
  • No implementar la lógica principal en Main.java.
  • No imprimir dentro de los métodos evaluados.
  • No usar Stream API ni Collectors.
  • No usar List.sort ni Collections.sort.
  • No usar librerías externas.

10. Entregables

Las clases y archivos deberan estar en sus paquetes correspondientes y el repositorio debe contener al menos los siguientes archivos:
  • PackageDimensions.java
  • Shipment.java
  • ShipmentData.java
  • ShipmentController.java
  • Main.java
  • README.md

El repositorio debe contener los commits realizados durante el examen y estar accesible para revisión. Un repositorio sin código subido no será evaluado.
