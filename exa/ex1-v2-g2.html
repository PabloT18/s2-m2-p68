ACTIVIDADES POR DESARROLLAR

1. Contexto

Una empresa de desarrollo registra proyectos de software con código, nombre, prioridad y métricas de planificación. Se debe implementar una clase controladora que filtre, ordene, elimine duplicados y clasifique los proyectos.

Se evaluará la selección de las implementaciones de colecciones más adecuadas. El enunciado define las interfaces de retorno y el orden requerido, pero no indica qué implementación concreta debe utilizarse.

2. Creación y entrega del proyecto

  1. Crear un proyecto Java nuevo.
  2. Crear los paquetes models, controllers y data.
  3. Descargar el archivo ProjectData.java proporcionado por el docente.
  4. Copiarlo sin modificaciones dentro del paquete data.
  5. Crear un repositorio personal en GitHub y subir el proyecto completo.
  6. Entregar en el AVAC únicamente el enlace del repositorio.

3. Modelos obligatorios

Crear la clase ProjectMetrics dentro del paquete models.

public class ProjectMetrics {
    private double estimatedHours;
    private int teamSize;
    private int completedTasks;
    private int pendingTasks;
}

Debe incluir el constructor con los cuatro atributos, sus getters y el método:

public double getWorkload()

La carga de trabajo se calcula con:

estimatedHours * teamSize

Crear la clase SoftwareProject dentro del paquete models.

public class SoftwareProject {
    private String projectCode;
    private String projectName;
    private ProjectMetrics metrics;
    private int priority;
}

Debe incluir el constructor con los cuatro atributos y sus getters. No agregar lógica de ordenamiento ni clasificación dentro de los modelos.

5. Método A: filterAndOrderProjects

Retornar los proyectos cuya carga de trabajo sea mayor o igual a minimumWorkload.

Se pueden crear métodos auxiliares.

Unicidad lógica:

  • Dos proyectos son duplicados cuando tienen la misma carga de trabajo y el mismo código ignorando mayúsculas y minúsculas.
  • Solo debe conservarse una aparición.

Orden obligatorio:

  • Carga de trabajo descendente.
  • Si la carga de trabajo es igual, código del proyecto ascendente.
  • La comparación del código debe ignorar mayúsculas y minúsculas.

Condiciones:

  • El resultado debe permanecer ordenado automáticamente.
  • No ordenar primero una lista para después convertirla al tipo de retorno.
  • La estructura concreta debe justificarse en el README.md.

6. Método B: classifyAndExtractProjects

Clasificar todos los proyectos mediante una estructura clave-valor y retornar únicamente los objetos de la categoría solicitada en requestedCategory.

Categorías:

  • CRITICAL: carga de trabajo mayor o igual a 900 o cantidad de tareas pendientes mayor o igual a 18.
  • STANDARD: carga de trabajo mayor o igual a 350, siempre que no sea CRITICAL.
  • SMALL: los demás proyectos.

Unicidad lógica:

  • Dos proyectos son duplicados dentro de una categoría cuando tienen la misma prioridad y el mismo código ignorando mayúsculas y minúsculas.

Reglas del agrupamiento:

  • La clasificación completa debe construirse antes de obtener la categoría solicitada.
  • Las claves deben ser exactamente CRITICAL, SMALL y STANDARD.
  • Las claves deben mantenerse ordenadas alfabéticamente.
  • Cada grupo debe eliminar duplicados y mantenerse ordenado automáticamente.

Orden dentro de cada categoría:

  • Prioridad descendente.
  • Si la prioridad es igual, código del proyecto ascendente.
  • La comparación del código debe ignorar mayúsculas y minúsculas.

Retorno:

  • Retornar una nueva lista con los objetos de la categoría solicitada.
  • La categoría recibida debe procesarse ignorando espacios externos y mayúsculas.
  • Si la categoría es nula o no existe, retornar una lista vacía.
  • No se permite filtrar directamente solo la categoría solicitada.

7. Prueba mínima desde Main.java

List<SoftwareProject> projects = ProjectData.createProjects();

ProjectController controller = new ProjectController();

Set<SoftwareProject> ordered =
        controller.filterAndOrderProjects(projects, 500);

List<SoftwareProject> critical =
        controller.classifyAndExtractProjects(projects, "CRITICAL");

System.out.println("Method A: " + ordered.size());
System.out.println("CRITICAL: " + critical.size());

8. README.md obligatorio

Explicar para cada método:

  • Implementaciones concretas seleccionadas.
  • Razón de la selección.
  • Cómo se garantiza el orden.
  • Cómo se eliminan duplicados.
  • Complejidad temporal principal.

9. Restricciones

  • No modificar ProjectData.java.
  • No cambiar nombres, parámetros ni tipos de retorno de los métodos.
  • No implementar la lógica principal en Main.java.
  • No imprimir dentro de los métodos evaluados.
  • No usar Stream API ni Collectors.
  • No usar List.sort ni Collections.sort.
  • No usar librerías externas.

10. Entregables

Las clases y archivos deberán estar en sus paquetes correspondientes y el repositorio debe contener al menos los siguientes archivos:

  • ProjectMetrics.java
  • SoftwareProject.java
  • ProjectData.java
  • ProjectController.java
  • Main.java
  • README.md

El repositorio debe contener los commits realizados durante el examen y estar accesible para revisión. Un repositorio sin código subido no será evaluado.
