1. Contexto

El departamento de infraestructura tecnológica registra solicitudes de mantenimiento con código, nombre del equipo, urgencia y métricas de atención. Se debe implementar una clase controladora que filtre, ordene, elimine duplicados y clasifique las solicitudes.

Se evaluará la selección de las implementaciones de colecciones más adecuadas. El enunciado define las interfaces de retorno y el orden requerido, pero no indica qué implementación concreta debe utilizarse.

5. Método A: filterAndOrderRequests

Retornar las solicitudes cuyo impacto sea menor o igual a maximumImpact.

Se pueden crear métodos auxiliares.

Unicidad lógica:

  • Dos solicitudes son duplicadas cuando tienen el mismo impacto, la misma urgencia y el mismo código ignorando mayúsculas y minúsculas.
  • Solo debe conservarse una aparición.

Orden obligatorio:

  • Impacto ascendente.
  • Si el impacto es igual, urgencia descendente.
  • Si el impacto y la urgencia son iguales, código de solicitud descendente.
  • La comparación del código debe ignorar mayúsculas y minúsculas.

Condiciones:

  • El resultado debe permanecer ordenado automáticamente.
  • No ordenar primero una lista para después convertirla al tipo de retorno.
  • La estructura concreta debe justificarse en el README.md.

6. Método B: classifyAndExtractRequests

Clasificar todas las solicitudes mediante una estructura clave-valor y retornar únicamente los objetos de la categoría solicitada en requestedCategory.

Categorías:

  • URGENT: urgencia mayor o igual a 5 o revisiones pendientes mayor o igual a 18.
  • PLANNED: impacto mayor o igual a 700, siempre que no sea URGENT.
  • ROUTINE: las demás solicitudes.

Unicidad lógica:

  • Dos solicitudes son duplicadas dentro de una categoría cuando tienen la misma cantidad de revisiones pendientes, el mismo impacto y el mismo código ignorando mayúsculas y minúsculas.

Reglas del agrupamiento:

  • La clasificación completa debe construirse antes de obtener la categoría solicitada.
  • Las claves deben ser exactamente PLANNED, ROUTINE y URGENT.
  • Las claves deben mantenerse en orden alfabético descendente.
  • Cada grupo debe eliminar duplicados y mantenerse ordenado automáticamente.

Orden dentro de cada categoría:

  • Revisiones pendientes ascendentes.
  • Si las revisiones pendientes son iguales, impacto descendente.
  • Si ambos valores son iguales, código de solicitud ascendente.
  • La comparación del código debe ignorar mayúsculas y minúsculas.

Retorno:

  • Retornar una nueva lista con los objetos de la categoría solicitada.
  • La categoría recibida debe procesarse ignorando espacios externos y mayúsculas.
  • Si la categoría es nula o no existe, retornar una lista vacía.
  • No se permite filtrar directamente solo la categoría solicitada.
