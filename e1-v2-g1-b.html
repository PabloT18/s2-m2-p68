1. Contexto de la evaluación

En un sistema de inventario de laboratorio se registran insumos tecnológicos disponibles para prácticas académicas. Cada insumo contiene información básica sobre el código del recurso, el responsable del área y la cantidad disponible en stock.

El objetivo de esta evaluación es implementar una clase controladora que procese una lista de insumos usando correctamente estructuras Set y Map.

En el enunciado se entregan los nombres de los métodos y sus parámetros, pero no se entrega el tipo de retorno. Se debe definir correctamente según la lógica solicitada.

5. Método A: filterAndSortSupplies

Implementar el método filterAndSortSupplies(List<LabSupply> supplies, int minimumStock).

Este método debe filtrar y ordenar insumos según el stock mínimo indicado.

Reglas funcionales:

  • Recibe una lista de insumos de laboratorio.
  • Recibe un número entero que representa el stock mínimo.
  • Solo se deben considerar insumos con stock mayor o igual al stock mínimo.
  • El resultado debe eliminar duplicados lógicos.
  • El resultado debe quedar ordenado automáticamente desde la estructura seleccionada.

Reglas de ordenamiento:

  • Ordenar por stock de forma descendente.
  • Si dos insumos tienen el mismo stock, ordenar por código de forma ascendente.
  • La comparación del código debe ignorar mayúsculas y minúsculas.

Regla de unicidad:

  • Dos insumos se consideran duplicados si tienen el mismo código ignorando mayúsculas y el mismo stock.
  • Cuando exista un duplicado lógico, solo debe conservarse un registro.

Implementación esperada:

  • Debe utilizar una estructura de tipo Set.
  • La implementación seleccionada debe permitir ordenamiento automático.
  • El ordenamiento y la unicidad lógica deben resolverse mediante un comparador.

6. Método B: groupCodesByStock

Implementar el método groupCodesByStock(List<LabSupply> supplies).

Este método debe agrupar insumos según el rango de stock disponible.

Rangos obligatorios:

  • HIGH: stock mayor o igual a 50.
  • MEDIUM: stock mayor o igual a 20 y menor a 50.
  • LOW: stock menor a 20.

Reglas funcionales:

  • El resultado debe organizarse por clave de rango de stock.
  • Las claves del mapa deben ser exactamente HIGH, LOW y MEDIUM.
  • Las claves deben mantenerse ordenadas alfabéticamente.
  • El valor asociado a cada clave debe contener los valores únicos de la sección YYY del código.
  • Se debe almacenar únicamente la sección YYY del código, no objetos LabSupply.

Regla de códigos:

  • El código tiene el formato AB-XXX-YYY.
  • Para el agrupamiento solo se debe tomar la sección YYY.
  • Si el insumo es IN-205-104, solo se debe almacenar 104.
  • La unicidad se determina por el valor YYY.
  • Si existen valores YYY repetidos dentro del mismo grupo, solo se debe conservar una aparición.
  • Los valores YYY dentro de cada grupo deben estar ordenados ascendentemente.

Ejemplo:

new LabSupply("IN-202-102", "Sofia Cordero", 55)
new LabSupply("IN-206-106", "Carlos Mendez", 90)
new LabSupply("in-209-102", "Ana Torres", 70)

En este caso, dentro del grupo HIGH se deben almacenar los valores 102 y 106. El valor 102 no debe repetirse.

Implementación esperada:

  • Debe utilizar una estructura de tipo Map para agrupar por rango.
  • Debe utilizar una estructura de tipo Set para evitar valores YYY duplicados dentro de cada grupo.
  • El mapa debe mantener las claves ordenadas alfabéticamente.
  • El conjunto de valores YYY debe mantenerse ordenado ascendentemente.
